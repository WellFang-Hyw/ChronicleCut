# 历史解说视频 v1 实现计划（影视切片 + 剪辑标注）

> **For Hermes:** 用 subagent-driven-development 逐任务实现本计划；每个任务完成后跑一次
> `run.bat test`（当前 203 项，零成本）再提交。

**Goal:** 在现有 `historical_story_gen` 流水线上，跑通一期「脚本朗读 + 影视切片背景 + 剪辑标注元素」的完整成片。以「三国·曹操」为验证题材。

**Architecture:** 保持现有的「分镜片段化编码 + concat 无损拼接」结构不变，在它两侧各加一层：
下游加**素材层**（影视切片库 + 索引检索），上游加**编辑决策层**（把脚本翻译成镜头表 EDL）。
渲染层只新增一种「视频背景」的编码路径，其余（定格、放大、标注）全部复用现有
「一张背景 + 一张前景 PNG + 一条 ASS + 一段语音」的机制 —— 这是本计划最大的复用点。

**Tech Stack:** Python 3.11 / ffmpeg 8.1.1 / Pillow / DeepSeek（出 EDL 文案）/ 现有 hsg 包

**范围（v1 只做这些）:**
- 素材：**人工剪辑 + 人工标记**，不做自动视频索引（那是独立工程）
- EDL：**模板生成 + 手改 JSON**，LLM 出文案放 v1.5
- 标注元素：人名条 / 大字标题 / 定格放大 / 指向箭头（4 个够用）
- 只支持横屏 1920x1080（影视切片是横屏素材，竖屏另议）

**不做（YAGNI）:** 自动人脸识别、自动分镜切分、地图/时间轴/关系图模板、
竖屏版的切片适配、多语种、在线素材搜索。

## 一、素材规范（你要按这个剪，工具才能吃进去）

人工剪片时的硬性要求，导入工具会校验并拒绝不合规的：

| 项 | 要求 | 为什么 |
|---|---|---|
| 单片段时长 | **6–10 秒** | 合规缓解（单段短）+ 剪辑节奏 |
| 画幅 | 1920x1080，30fps | 与成片一致，避免重编码变形 |
| **音轨** | **必须去掉** | 不用原声（版权），且我们有自己的配音 |
| 容器/编码 | mp4 / h264 + yuv420p | 与 concat 兼容 |
| 命名 | 随意，导入时给 id | id 是检索用的键 |
| 标注 | 剪的时候**不要**加字幕/水印 | 我们自己叠标注层，避免双重文字 |

导入时你还要提供这几个标签（决定了流水线能不能检索到它）：

    片源名 + 年份     例：三国演义 / 1994
    人物              例：曹操、荀彧、许褚（可多个）
    年代              例：东汉末
    题材              例：三国
    时间码 + 一句话描述  例：00:12:30 横槊赋诗前的特写

## 三、EDL（编辑决策文件）的结构

这是整套东西的枢纽。一句话：**把"脚本分镜"翻译成"镜头表"**。

```json
{
  "version": 1,
  "topic": "曹操",
  "scenes": [
    {
      "index": 4,
      "shots": [
        {"kind": "clip", "src": "sg_caocao_07", "in": 1.2, "out": 6.8, "motion": "none"},
        {"kind": "freeze", "src": "sg_caocao_07", "at": 4.0, "dur": 2.5,
         "zoom": 1.6, "focus": "face",
         "callout": {"text": "枭雄", "style": "big", "pos": "right"},
         "nameplate": {"name": "曹操", "role": "魏武帝"}}
      ]
    }
  ]
}
```

字段约定：
- 每个 `scene.index` 必须对应脚本里的分镜号；`shots` 时长之和必须等于该分镜语音时长 + tail_padding（校验会拦）
- `kind` 支持 `clip`（影视切片）/ `still`（现有静态图）/ `freeze`（从切片抽帧当静态画面）
- `motion` 沿用现有 `motion_mode` 的 0-3（缓移方向）
- `focus` 取值 `face` / `center` / `left` / `right` —— 决定放大时裁切哪块（v1 不做人脸检测，用画面比例框 + 你手改）

### T2 导入工具：规范化 + 登记  ✅ 已完成（`c763d0e`）
**Files:** Create `scripts/import_clip.py`；Modify `src/hsg/clips.py`
**Objective:** 把你剪好的 mp4 转成统一规格、**剥掉音轨**、写出规范化文件并登记进索引。
**关键代码**（这是最容易踩坑的一步）：

```python
# 规范化：统一规格 + 去音轨 + 限制时长（-an 是关键，原声绝对不能留）
def normalize_clip(src: Path, dest: Path, spec: dict, max_seconds: float) -> float:
    dur = min(media_duration(src), max_seconds)
    run_ffmpeg(["-i", str(src), "-t", f"{dur:.3f}", "-an",
                "-vf", (f"scale={spec['width']}:{spec['height']}:"
                        "force_original_aspect_ratio=increase,"
                        f"crop={spec['width']}:{spec['height']},fps={spec['fps']}"),
                "-c:v", "libx264", "-pix_fmt", "yuv420p", "-crf", "18",
                "-movflags", "+faststart", str(dest)],
               cwd=dest.parent, desc="normalize_clip")
    return dur
```
**验收：**
- 导入一条后用 `ffprobe` 确认：无音轨、1920x1080、30fps、时长 ≤10s
- **用 volumedetect 确认没有声音残留**（`mean_volume` 应为 -inf 或没有 audio 流）
- `data/clips/index.json` 里出现这条记录，含 title/year/people/era/dur
- 超过 10 秒的输入被**截断**而不是报错（且日志给出提示）
**提交**：`feat(clips): 导入工具（规范化 + 去音轨 + 登记）`

### T2.5 素材需求清单（脚本先行的那一环）  ✅ 已完成
**Files:** Create `src/hsg/needs.py`、`scripts/make_needs.py`；Modify `config.yaml`、`scripts/test_verify.py`
**为什么要有这个（原计划漏了）：** 用户提的「脚本先行」——
顺序必须是 **脚本 → 需求清单 → 按单剪素材 → 导入 → 渲染**。
剪素材是最慢的人工环节，先剪后配会剪一堆用不上的；清单是用户剪素材的工作单，
所以它不能等 EDL（T7）产出，必须独立排在这一步。

**关键设计（每条都有踩坑记录）：**
- **两级粒度**：槽位粒度 = 画面切点（`s04_sh1`），素材粒度 = 一个片段。
  22 秒的分镜、单段上限 10 秒 → 切 3 段。但**每个分镜只有第 1 段要真剪**，
  第 2 段起标「↺ 复用」（同场戏的不同时刻/轻微推拉铺满）。
  不做这个区分，一期会变成 58 条「必须」，没人剪得完。
- **优先级只认章节开场**，且只标在第 1 段上 → 「先剪这几条」是 3-6 条。
- **回退方案**（找不到素材时）：关键位置/长分镜 → AI 生成；其余 → 现有静态配图。
  不能卡住整期。
- **时长三级取值**：实测音频 > metadata 的实测 `seconds` > 按字数估（只有 plan 产物走估算）。
- **一次便宜的 LLM 调用**补 `need`（可照着找的镜头描述）/`people`/`callout`（2-4 字标注词）；
  异常退回规则值，不阻断出清单。
- **覆盖度报告**：已绑定 / 有候选 / 还缺（关键位置单独列），外加
  「真要剪多少秒」——把工作量说清楚。

**产物：** `data/needs/<日期>_<题材>_素材需求.md`（照剪）+ `.json`（EDL 装配用）
**验收（实测）：** 驿站 plan 产物 → 41 槽位 / 9 段要剪 / 必剪 3 条；
第 7 期 → 58 槽位 / 18 段要剪 / 必剪 6 条；测试 230 → 287 项全过，死配置 0 项。

### T6 场景级贴回语音
**Files:** Modify `src/hsg/video.py`（新增 `attach_audio`）
**Objective:** 把多镜头拼成的"无声场景段"贴上该分镜的完整语音。

## 五、风险与已知局限

| 风险 | 现状 | 应对 |
|---|---|---|
| 影视切片版权 | 灰色，无法消除 | 单段 ≤10s + 去原声 + 加解说与标注（转换性）+ 标出处 + 占比上限 |
| 素材人脸一致性 | 切片是真人，跨镜头人不同 | 靠人名条标注"这是谁"来弥补，v1 接受 |
| 自动检索人物 | 需要视频索引系统 | **v1 不做**，人工打标签 |
| 竖屏版 | 切片是横屏 | v1 只出横屏；竖屏要么中间裁切要么上下加虚化边（v2） |
| 音效 | 没有免版权音效库 | v1 先不加音效；v1.5 建音效库（Commons / mixkit，注意 Free/Restricted） |
